# Лабораторная работа №6 - Generics и typing

## 1. Цель работы

Освоить систему аннотаций типов в Python (typing). Научиться создавать обобщённые (generic) классы с помощью TypeVar и Generic. Понять концепцию структурной типизации через typing.Protocol.

## 2. Описание реализованных типов и контейнеров

### Generic-класс TypedCollection[T]

Реализован обобщённый класс-контейнер TypedCollection, который может хранить объекты любого типа, указанного при создании. Класс поддерживает основные методы работы с коллекцией: add, remove, get_all, а также методы высшего порядка find, filter, map. Все методы снабжены аннотациями типов.

### TypeVar

Использованы четыре параметра типа: T - для хранения элементов коллекции (без ограничений), R - для типа результата при преобразовании map, D - с ограничением bound=Displayable (только объекты с методом display), S - с ограничением bound=Scorable (только объекты с методом score).

### Протоколы

Созданы два протокола: Displayable требует наличия метода display() -> str, Scorable требует наличия метода score() -> float. Протоколы реализуют структурную типизацию: класс не обязан явно наследоваться от протокола, достаточно просто иметь нужные методы. Классы Book и VideoGame соответствуют обоим протоколам без явного наследования.

## 3. Демонстрация работы

### Сценарий 1: TypedCollection[T] (Generic коллекция)

Создаются коллекции с разными типами данных: строки и объекты Product. Это демонстрирует, что один и тот же класс может работать с любым типом.

![01](https://github.com/Raelag2/oop_labs/blob/main/images/lab07/1.jpg)

### Сценарий 2: Методы find, filter, map

Демонстрируются методы высшего порядка. find ищет первый подходящий элемент (возвращает элемент или None). filter возвращает список всех подходящих элементов. map преобразует элементы с изменением типа результата (из Product в str и float).

![02](https://github.com/Raelag2/oop_labs/blob/main/images/lab07/2.jpg)

### Сценарий 3: TypedCollection[D] (Displayable)

Создаётся коллекция с ограничением Displayable. В неё добавляются объекты разных типов - Book и VideoGame. Ни один из этих классов не наследуется от протокола Displayable, но оба имеют метод display(). Это демонстрирует принцип структурной типизации: важны методы, а не наследование.

![03](https://github.com/Raelag2/oop_labs/blob/main/images/lab07/3.jpg)

### Сценарий 4: TypedCollection[S] (Scorable)

Этот сценарий показывает, что тот же самый класс TypedCollection может работать с другим ограничением - Scorable. В коллекцию добавляются объекты Book и VideoGame, у которых есть метод score(). Один класс TypedCollection успешно используется с разными протоколами.

## 4. Вывод

В ходе лабораторной работы изучены аннотации типов, которые позволяют указывать ожидаемые типы параметров и возвращаемых значений, что улучшает читаемость кода и помогает IDE давать подсказки. Освоены Generic и TypeVar, дающие возможность создавать классы и функции, работающие с разными типами, сохраняя при этом типизацию и избегая дублирования кода. Изучен Protocol как способ структурной типизации - вместо явного наследования класс подходит под протокол автоматически, если у него есть нужные методы. Это делает код более гибким. Типизация помогает отлавливать ошибки на этапе разработки и делает код самодокументируемым.
